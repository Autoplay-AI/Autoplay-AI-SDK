There are **two independent ways** to bring a user's real-time in-app activity into Intercom. They solve the same problem from opposite directions — start by picking the one that fits. You can also run both.

## Choose your integration path

<CardGroup cols={2}>
  <Card title="Push into conversations" icon="tower-broadcast" href="/recipes/intercom-tutorial/step-1-connect-real-time-events">
    **Your backend** streams Autoplay events and writes internal notes into conversations as they happen. Notes appear automatically for your team — no agent setup needed.
  </Card>

  <Card title="Let Fin pull on demand" icon="plug" href="/recipes/intercom-tutorial/let-fin-pull-live-activity">
    **Fin fetches** a user's recent activity itself, only when it's about to answer. The lightest setup — no streaming worker to host.
  </Card>
</CardGroup>

## Which should I choose?

| | **Push** (steps 1–2) | **Pull** (Fin) |
| --- | --- | --- |
| Who acts | Your backend | Intercom Fin |
| When | Continuously, as events arrive | On demand, when Fin answers |
| You host | A worker that consumes the SSE stream + a public webhook endpoint | Nothing — Fin calls the connector directly |
| Result | Internal notes in every conversation | Fin's answers reflect what the user just did |
| Best for | Always-on context visible to human teammates | Letting Fin self-serve context with minimal infra |
| Identity | Session ↔ conversation linking | Messenger JWT so Fin sends a verified `user_id` |

<Note>
  Not sure? If your goal is simply **"Fin knows what the user just did,"** start with **[Let Fin pull on demand](/recipes/intercom-tutorial/let-fin-pull-live-activity)** — it's the shortest path and needs no backend service.
</Note>

## 📋 Prerequisites

**Both paths** need a working [Quickstart](/quickstart): the PostHog snippet, `posthog.identify(...)`, a registered product, and the PostHog webhook — so activity is flowing into the connector.

**Push additionally needs:**

- **A public HTTPS URL you control** — for Intercom to `POST` webhook payloads to.
- **A stream consumer** — a worker that opens the Autoplay SSE stream (`autoplay-sdk` installed; the test stream from the Quickstart working).

**Pull needs nothing extra to host** — just your connector URL + API token, and (for logged-in users) Messenger JWT identity verification, covered in its recipe.
